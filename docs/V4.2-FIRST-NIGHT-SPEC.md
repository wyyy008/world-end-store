# V4.2 商业试玩版 · 第一夜规格与阶段计划

## 目标与边界
- 定位：20–30 分钟单机试玩；收银操作 → 异常调查 → 证据推理 → 第三次门铃 → 选择后果。
- 本阶段仅增强第一夜调查阶段，不替换八夜剧情，不新增存档字段，不改变 v5 版本号和 localStorage 键。
- 基线：继承 V4.1 P0 分支。正式发布前必须单独验证该分支与 main 的差异。
- 第一阶段实现：可选的「收据 + 监控」证据对照、记忆册记录、响应式样式、回归测试。未找到两项证据时禁用对照；仍可按原规则收集任意两条线索后开门。

## 详细功能规格
### A. 收银与异常收据（已有）
1. 扫描雨伞、咖啡和纸袋，显示逐件金额及合计。
2. 付款 ¥50，正确找零 ¥30；错误可重试。
3. 展示来自「明日 00:17」的小票，进入阿澄及调查剧情。
验收：金额与库存一致；错误输入不改变库存；刷新后能恢复阶段。

### B. 调查与推理（阶段一实现）
1. 调查收据背面、监控、站牌任意三处；已发现证据可以重看。
2. 当且仅当收据与监控都已发现时，解锁「对照收据与监控」按钮。
3. 点击对照后，写入现有 flags.firstNightTimeDeduction=true，添加一次记忆，反馈「00:17」的时间矛盾。
4. 再次点击不重复写入记忆；刷新后仍显示推理已完成。
5. 该推理是可选深度玩法：旧存档和只查到另外两条线索的玩家，仍可进入第三次门铃。
验收：缺少线索时无法触发；两线索齐全后触发一次；不阻断旧剧情。

### C. 第三次门铃（保留原逻辑）
- 原有 open/wait/verify 三种决策不变；verify 仍需监控线索。
- 已实现：第二夜开场根据第一夜 open/wait/verify 三种决策展示不同旁白；完成额外推理时追加一条 00:17 的回忆。两条路线均使用现有开场函数，不更改原剧情节点。
- 旧存档没有上述标记时，继续原来的第二夜开场，不增加额外旁白。

## 技术架构
- 阶段一：保留原脚本加载顺序、全局状态和 commit() 保存机制，使用既有 flags 容器保存新成就式推理状态。
- 阶段二：将第一夜数据、推理条件与 UI 渲染拆为独立模块，并增加可测试的纯函数；必须先做快照与旧存档回归。
- 阶段三：商业发行的多存档槽、自动存档、日志与输入无障碍、Windows 容器打包；不在本阶段一次性迁移存档。

## 测试标准
- 语法：node --check game.js、content.js、audio.js、save-tools.js。
- 自动化：node --test tests/p0-regression.test.cjs tests/v42-first-night.test.cjs。
- 浏览器：1920×1080、1366×768、390×844、375×667；鼠标、键盘、触屏可操作，焦点可见。
- 存档：全新 v5、V4 旧 v5、第一夜调查中断、第二至第八夜存档，导入/导出后流程一致。
- 路线：八夜全通关、两条路线、三种访客决策、刷新与继续游戏、错误找零。
- 性能：首次加载与场景切换无明显长时间卡顿；正式测试需记录实际数据。
- 发布门槛：所有 P0 测试通过、无阻断问题、旧存档通过、素材许可明确、20 位陌生玩家测试第一夜。
