# 交互设计与实现

先追踪真实状态、事件处理器、存档机制及第一夜流程。不得直接按假想数据结构编码。

## 核心原则
- 每次交互遵循：可发现的目标 → 明确动作 → 即时视听反馈 → 状态变化 → 剧情后果。
- 第一夜重点核实三件商品收银、找零重试、异常小票、阿澄、两条线索与第三次门铃。
- 阅读与思考暂停营业时间；只有已定义的经营行动消耗时间。
- 选择产生情感与叙事差异，而非单纯加减好感度。
- 交互应可用鼠标、触屏与键盘完成；不要依赖 hover 才能发现热点。

## 实现流程
1. 画出当前事件状态转换：idle → inspecting → feedback → resolved。
2. 明确状态的唯一来源、是否持久化、是否可能重复执行。
3. 为点击、错误、成功、不可操作、完成增加清晰反馈。
4. 动画期间防重复提交；允许安全跳过演出但不跳过状态提交。
5. 刷新恢复时确保库存、金钱、行动格、线索不会重复变化。
6. 优先修改现有函数与样式，不引入无必要的框架。

## 验收场景
- 连续快速点击不会重复扣费或推进两次剧情。
- 错误找零可重试，正确找零后状态一致。
- 未满足线索条件时提示明确，满足条件后正常推进。
- 手机触摸操作、窗口缩放、刷新与继续游戏均正常。
